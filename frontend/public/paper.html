Modelling the Energy Output of a Fixed PV Array in New Zealand from Satellite-Derived CAMS Radiation Data

A physics-first solar-PV simulation: astronomical solar geometry, the Copernicus CAMS Radiation Service, and their realisation in a Python / pvlib / FastAPI / React stack.

1. Abstract

This paper documents the mathematical model behind a location-switchable photovoltaic (PV) energy simulator for two New Zealand cities, Auckland (36.73° S, 174.71° E) and Christchurch (43.54° S, 172.70° E). The model consumes 15-minute, satellite-derived irradiation from the CAMS Radiation Service and converts it, interval by interval, into the expected electrical energy of a fixed, user-configured PV array. The conversion follows a well-established, physics-first pipeline: solar position → plane-of-array (POA) irradiance → DC/AC power → energy. All solar-geometry and transposition mathematics is delegated to the pvlib-python library rather than being re-implemented, so the model can be validated against published references. This document describes the raw data sources, the governing equations, the Python realisation, the API and frontend, and the model’s assumptions and validation.

2. Introduction & Objectives

A PV panel is only useful if we can predict, for a given location and orientation, how much electrical energy it will produce over time. The fundamental challenge is that a solar-radiation dataset (such as CAMS) reports radiation onto specific reference planes — horizontal (GHI) or perpendicular to the sun (DNI) — while the panel is tilted and oriented arbitrarily. The essential transformation is therefore:

CAMS irradiance → solar position → Plane-of-Array (POA) irradiance → PV power → energy

The model is deliberately idealised in its first version: it models the energy a panel would produce given the measured radiation, ignoring module temperature, soiling, shading, mismatch and degradation. These are treated as explicit, pluggable loss terms that can be added without altering the geometric core. A clear-sky (no-cloud) reference output is also computed so the effect of clouds can be seen at a glance.

3. Raw Data Sources

3.1 The CAMS Radiation Service

The driving resource data are provided by the Copernicus Atmosphere Monitoring Service (CAMS) — ads.atmosphere.copernicus.eu. The CAMS Radiation Service (v4.6, all-sky) is derived from satellite observations: visible-channel imagery from geostationary satellites is used, via the Heliosat method, to estimate cloud cover and thus the surface shortwave irradiance. Two families of fields are returned for every grid cell:

  • All-sky values, which account for the actual observed clouds; and
  • Clear-sky values, the radiation that would arrive in a cloud-free atmosphere.

The exported fields are (per 15-minute interval):

Export columnMeaning
GHIGlobal irradiation on a horizontal plane at ground level
BHIBeam (direct) irradiation on a horizontal plane
DHIDiffuse irradiation on a horizontal plane
BNIBeam irradiation on a plane normal to the sun
Clear-sky GHI / BHI / DHI / BNIthe same four, for a cloud-free sky
ReliabilityProportion of reliable satellite data in the interval (0–1)

The CAMS fields are irradiations (energy per unit area over the interval, in Wh/m²), not instantaneous irradiances (W/m²). The loader therefore divides each interval value by the interval duration in hours to recover the average irradiance in W/m² (see §5.1). BNI is effectively the direct normal irradiance (DNI) that pvlib expects, and BHI is the direct component of the horizontal irradiance. The observations are tagged with the site’s latitude, longitude and altitude in the file header, which the loader parses so the model is self-describing and can be switched between cities without code changes.

3.2 The Astronomical (solar-position) model

Independently of the satellite data, the sun’s position in the sky at any instant is needed to project radiation onto a tilted panel. The model uses pvlib’s implementation of the NREL Solar Position Algorithm (SPA) (Reda & Andreas, 2004). Given the geographic position, the altitude, the UTC time and a small set of constants (air pressure, temperature, delta-T), the SPA computes, per timestamp:

  • solar zenith angle z and its apparent (refraction-corrected) value;
  • solar elevation α = 90° − z;
  • solar azimuth γ, measured clockwise from North.

The SPA is accurate to about 0.0003° and is the de-facto reference used in solar engineering; using it frees the model from having to reproduce astronomy by hand, which was a key design decision of the project.

Both sites are in the Southern Hemisphere, so the sun’s apparent path crosses the northern sky; a north-facing panel (azimuth 0°) therefore captures the most energy over the year. New Zealand observes daylight saving (NZST = UTC+12, NZDT = UTC+13), which the time handling must respect.

4. Coordinate and Time Conventions

  • Azimuth follows the meteorological convention: 0° = North, 90° = East, 180° = South, 270° = West.
  • Tilt is measured from horizontal: 0° = flat, 90° = vertical.
  • Timestamps are stored and processed as timezone-aware UTC datetimes, and displayed in the local zone Pacific/Auckland. This avoids daylight-saving bugs: a naive timestamp would be ambiguous across the NZST/NZDT transition.

5. Theory: From Irradiance to Electrical Energy

5.1 Units: irradiation vs irradiance

CAMS delivers irradiation (Wh/m² accumulated over 15 min). The instantaneous quantity used by the transposition physics is the irradiance (W/m²), the time-averaged power density. For an interval of duration Δt hours,

G[W/m²] = E[Wh/m²] / Δt[h]

with Δt = 0.25 h for the 15-minute CAMS grid. After this step, and mapping BNI→DNI, the model works entirely in W/m² and reconstructs energy at the end by multiplying power by Δt.

5.2 Solar position

For every timestamp, the SPA yields the apparent solar zenith z and solar azimuth γ. The solar elevation is α = 90° − z. These quantities are used both for the transposition and as an explicit guard against numerical artefacts: when α ≤ 0° (night), output is forced to zero.

5.3 Angle of incidence

For a panel with tilt β and azimuth γpanel, the cosine of the angle of incidence (AOI) between the sun’s rays and the panel’s normal is computed by pvlib as

cos(AOI) = cos(z)·cos(β) + sin(z)·sin(β)·cos(γpanel − γ)

This geometric factor governs how much of the direct (beam) radiation actually lands on the panel face.

5.4 Plane-of-array (POA) irradiance

The irradiance on the tilted panel is the sum of three physically distinct contributions:

POA = POA_direct + POA_diffuse + POA_ground
  • Direct (beam): POA_direct = DNI · cos(AOI).
  • Diffuse (sky): computed from DHI and the panel geometry by a transposition / sky-diffuse model.
  • Ground-reflected: the fraction of global irradiance reflected by the ground onto the panel, POA_ground = GHI · ρ · (1 − cos(β)) / 2, where ρ is the albedo.

Three sky-diffuse transposition models are available: Perez (default; a two-term anisotropic model that accounts for the circumsolar and horizon brightening, using the DNI/extra-terrestrial ratio), Hay–Davies (an anisotropic model that weights direct-beam forward scattering), and the isotropic model, which assumes the diffuse sky is uniform so the diffuse factor is simply (1 + cos(β)) / 2. The Perez model typically gives the closest agreement with measured tilted irradiance.

5.5 From POA to power

The idealised model assumes the DC power scales linearly with plane-of-array irradiance relative to Standard Test Conditions (STC, 1000 W/m²), clipped at the rated power:

P_DC = min( P_STC · (POA / 1000 W/m²) , P_STC ),  and 0 when the sun is down

The AC power applies the inverter efficiency, assumed flat:

P_AC = ηinv · P_DC

with the default ηinv = 0.95 (a modern string inverter, typically 95–98%). Energy over the interval is then E = P_AC · Δt.

5.6 No-cloud (clear-sky) reference and the ceiling

By re-running the same pipeline with the clear-sky components (GHI_clear, DHI_clear, DNI_clear) and the same geometry, the model produces an AC power (clear sky) series: the output the panel would deliver with no clouds. Because clouds only attenuate radiation, this reference is treated as an upper bound, and the real output is clamped so it never exceeds it. In the low-sun evening regime a north-facing panel can otherwise show real > clear from the diffuse-transposition reacting to a (higher) cloudy-sky DHI, which is a known artefact that the clamp removes.

6. Realisation in Python

The implementation is organised into a thin data layer, a physics engine, and an HTTP API.

6.1 Data loader (api/loader.py)

Reads a CAMS CSV, skipping the #-comment header block, and parses the site latitude, longitude and altitude from that header. It normalises the CAMS column names to an internal schema (ghi, dhi, dni, ghi_clear, dhi_clear, dni_clear, reliability), converts Wh/m² to W/m² using §5.1, and returns a DataFrame indexed by a timezone-aware UTC DatetimeIndex. The loader also records the interval length so energy can be reconstructed later.

6.2 The engine (api/engine.py)

A single function, run_simulation, implements §5 in a few vectorised steps using pvlib:

  1. solarposition.get_solarposition → zenith, elevation, azimuth;
  2. irradiance.aoi → angle of incidence;
  3. irradiance.get_total_irradiance → POA (direct + diffuse + ground), for both all-sky and clear-sky inputs, using the configured transposition model and albedo;
  4. linear POA → DC power with rated-power clipping and night guards (α ≤ 0 or GHI ≤ 0 ⇒ 0);
  5. inverter efficiency → AC power; energy = AC · Δt;
  6. clamp real output to the clear-sky ceiling (§5.6).

The engine returns a full per-interval DataFrame (UTC timestamp, NZ-local timestamp, sun elevation/azimuth, AOI, GHI/DHI/DNI, all POA components, DC/AC power, clear-sky AC power, and energy), plus a small summary (total kWh, peak, specific yield, mean AC power, and the no-cloud total).

6.3 The API (api/index.py)

A FastAPI application exposes the model over HTTP. Each site’s dataset is cached in memory after first load (an lru_cache keyed by location). Endpoints:

EndpointPurpose
GET /api/healthhealth check
GET /api/locationsthe two switchable cities + metadata
GET /api/radiation/{location}normalised radiation, optional date slice
POST /api/simulaterun the model; body = location + panel config + date range

Panel configuration (tilt, azimuth, rated kWp, albedo, transposition model, inverter efficiency) is validated by Pydantic models. CORS is enabled so the browser frontend can call the API.

6.4 The frontend (React)

A React (Vite) application lets a user pick the location, tune the panel (with a live compass for azimuth), choose a date range, and view three charts (PV output with the no-cloud reference, irradiance components, and sun geometry) plus compact report cards (total, no-cloud, peak, yield, mean AC). The frontend performs no science: it only requests results from the API and plots them, which keeps the model reproducible.

7. Assumptions and Limitations

  • Idealised conversion: no module temperature, soiling, mismatch, shading, degradation, or wiring losses. Real systems therefore produce somewhat less than the ideal DC model predicts.
  • Flat inverter efficiency: a single scalar is used; real inverters are less efficient at partial load.
  • Fixed, unshaded panel: no tracking and no shading from the surrounding terrain or buildings.
  • Satellite resolution: CAMS irradiance is derived from satellite cloud retrievals; it is representative of the satellite pixel, not an on-site pyranometer.
  • No irradiation persistence: each 15-minute interval is treated independently.

These are explicit design choices (per the project brief) that make the model debuggable first, with each effect added as a transparent configuration parameter later.

8. Validation and Testing

The model is tested against internal consistency and known physical limits:

  • Energy conservation: in the raw CAMS data, GHI = BHI + DHI holds to within numerical rounding (mean residual ≈ 0.0000 Wh/m²).
  • Night: output is exactly zero at NZ-local midnight.
  • Seasonality: summer (December) energy exceeds winter (June) for a fixed panel in the Southern Hemisphere.
  • Geometry: a flat panel (tilt 0°) yields POA ≈ GHI on a bright day.
  • Linearity: DC power = P_STC · (POA/1000) with rated-power clipping.
  • Clear-sky ceiling: the real AC power never exceeds the clear-sky AC power (after §5.6).
